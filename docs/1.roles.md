## 3. GitLab Workflow

<!-- A brief description of how the team will use GitLab for version control, issue tracking, and collaboration -->

- All project files, including markdown documents, meeting logs and design assets, will be stored in the GitLab Repositories.
- Each team member will work on their own branch and create merge requests to merge changes into the main branch.
- Commit messages will follow a consistant format to ensure clarity and traceability.
- Team members will use Git push/pull features to keep branches up to date.
- Issues will be assigned to team members based on their roles.
- Any issues will be tracked using a progress table, and assigned to members based on their roles.
- Merge requests will be peer-reviewed before being merged to maintain quality and reduce errors.
